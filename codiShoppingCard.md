| Ventaja | Descripción |
| :--- | :--- |
| **Calidad del Código** | Permite que otros desarrolladores detecten errores, sugieran optimizaciones y aseguren que se sigan los estándares de codificación. |
| **Colaboración** | Fomenta la comunicación y el conocimiento compartido dentro del equipo sobre el código base. |
| **Rastreo y Documentación** | El historial de la PR (comentarios, aprobaciones, cambios) sirve como documentación histórica de por qué y cómo se introdujo un cambio. |
| **Prevención de Errores** | El código solo se fusiona en ramas estables después de ser validado, reduciendo la probabilidad de introducir *bugs*. |

## ➖ Desventajas (Consideraciones)

| Desventaja | Descripción |
| :--- | :--- |
| **Tiempo de Espera** | El proceso de revisión y aprobación puede ser lento, deteniendo el flujo de trabajo del desarrollador que espera la fusión. |
| **Sobrecarga de Revisión** | Si las PR son muy grandes o numerosas, pueden sobrecargar al equipo de revisión. |
| **Conflictos de Fusión** | Si dos ramas modifican el mismo código base, la PR puede requerir una resolución manual de conflictos antes de poder fusionarse. |
